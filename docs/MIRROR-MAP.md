# 镜城围攻路线调整

第 8 章改成东西镜像双翼，各自折返后在南侧汇合。两翼各有独立拦截点，南侧保留补防阵位；中央塔仍可支援，无法再沿重叠道路反复清理两路敌人。

地面单路长度由 1,820 调整到 1,680；相同尾段由 1,210 缩到 210，占全路从 66.5% 降至 12.5%。去掉自身重叠路段，飞行入口、终点和直线路程保持。16 个阵位重新安排，12 个免费、4 个付费，价格保持；所有阵位中心离道路中心至少 50。

按 263 射程计算，一座塔对两路地面路线的平均几何覆盖比例上限由 78.7% 降至 54.6%。这是线段与圆相交的长度，不是实战伤害；减速、目标选择、词义、飞行和敌人攻塔都会改变实际收益。可复现命令：

```sh
node scripts/audit-mirror-map.mjs --write
```

## 存档与手机操作

仍使用存档 v9。新建第 8 章战局写入 `mirrorLayout: 2`；未携带标记的既有第 8 章存档读取为 `mirrorLayout: 1`。旧局保留原路线、阵位、在场怪物坐标、范围区域、伤势、钱包、字牌、波次、队列及 RNG，继续无尽也沿用原地图。重新挑战或重新开启本章后使用新路线。其他章节不添加此字段。

新旧布局标记随怪物保存；后续排队出生、分身、召唤和援军继承当前战局的布局。界面绘图、阵位点击、射程判定与实际移动读取同一套地图。未知布局版本和矛盾的怪物布局会被拒绝。

小屏幕的 44 像素透明点击区域可能互相覆盖，现在点击时按屏幕坐标选择最近的阵位；键盘和程序触发仍使用按钮本身对应的阵位，避免后绘制的按钮抢走另一个阵位中心的触摸。

## 平衡结果

主线使用原有两种自动布阵策略（不开/开启主动落墨），每章同样的种子 1—20，按实际墨点、收入、维修和价格运行，无额外注资。爱心剩余且完成本章算通关，出现塔损毁不算失败。

| 第 8 章样本 | 通过 | 胜率 |
|---|---:|---:|
| 更新前，种子 1—20 × 两策略 | 40/40 | 100% |
| 更新后，相同种子与策略 | 19/40 | 47.5% |
| 更新后，额外种子 21—40 × 两策略 | 27/40 | 67.5% |
| 更新后，两组汇总 | 46/80 | 57.5% |

种子 1—20 参与了路线试调，21—40 在路线确定后用于追加检查；额外组没有用于后续调参。相同种子的两策略不是两张独立地图，这些结果也不是儿童实玩胜率。首组两策略失守最早在第 7/8 轮，额外组最早第 6/12 轮，均无超时。

完整十章 400 局由 319 胜调整为 298 胜，74.5%；其他九章的胜负、爱心和攻塔统计逐项与上版一致。本次没有改怪物、塔、收入或价格。第 5、9 章仍偏容易，整个十章没有因此变成严格单调曲线，不按固定胜率配额强改。

298 项规则测试通过；新增 4 项覆盖几何、上版真实存档、20 秒旧引擎轨迹回放、新旧队列/地面/飞行/分身/无尽和非法布局。Chromium 与 WebKit 的 320×568、393×852、667×375、1440×1000 均验证实际 Canvas 路线、旧局继续、确认重开、真实坐标落塔及扣费、双入口、暂停与重载、无溢出/脚本错误。WebKit 模拟独立窗口不能代替实体 iPhone 检查。
